## Decisões e alterações

Contrato TS de `propertyReadings`, criação pela API Firebase Auth + validador
Python real, snapshots com hash e origem, contador por imóvel em transação,
idempotência por `saveId`, paginação de histórico e índice. Regras negam qualquer
escrita direta; leitura restringe imóvel/agência atual. Como Admin SDK ignora
regras, autorização é repetida na transação da API, incluindo base da mesma
agência/imóvel. Não há endpoint de update/delete nem escrita de planta no imóvel.

Rota `/imoveis/planta?id=...` segue a exportação estática existente, reutiliza
capturador e mantém sandbox `/capturador` independente. Links nas duas áreas
do painel. Carregamento faz round-trip semântico sem perder campos. Novas versões
não aprovam nem criam pedidos/jobs. Script dev sobe a API só no emulador; CI do
emulador instala Python/requirements para exercitar a fronteira real.

Ver [decisão completa](../miniaturas/m1-d-persistencia-leitura.md), inclusive
limites de implantação. Não houve nova dependência npm, novo fluxo de login,
alteração de papéis, deploy, BuildJob, renderer, CV, LEVE ou Blender.
